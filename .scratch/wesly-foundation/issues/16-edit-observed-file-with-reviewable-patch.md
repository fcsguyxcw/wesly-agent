# 16 — 用可审查补丁修改已观察文件

**What to build:** Agent 可以修改已读取的普通工作区文本文件；执行前向用户展示差异，并以最新观察哈希保护目标，通过有界补丁和原子替换完成写入。

**Blocked by:** 15 — 完成只读仓库调查切片验收

**Status:** resolved

- [x] 成功读取文件后记录真实磁盘哈希，修改请求携带该版本前置条件。
- [x] 普通、非敏感、已存在的单文件修改在前置条件成立时可自动执行。
- [x] 执行前展示明确差异，写入采用补丁或原子替换。
- [x] 成功修改后重新读取磁盘哈希，并将新哈希作为最新观察版本。
- [x] 哈希冲突不覆盖用户变更，而是产生明确失败并要求重新调查。
- [x] 临时真实文件系统测试覆盖成功写入、冲突、半写入防护和历史哈希保留。

## Implementation result

- `read_file` 现在基于真实磁盘字节计算并返回 SHA-256；`ToolRegistry` 在当前运行内保留只增不减的读取/写入观察历史，并按路径维护最新观察版本。
- 新增有界 `apply_patch`：只接受工作区内、非敏感、已存在的 UTF-8 普通文件，要求最新观察哈希和精确出现一次的 `old_text`，单文件上限 1 MiB、补丁片段上限 32 KiB。
- Agent 先把不可变补丁预览作为 `FileDiffProposed` 事件交给 CLI 展示；没有预览的有效补丁以 `preview_required` 拒绝，预览与调用不一致也拒绝。
- 执行在暂存前和原子替换前分别复核磁盘哈希，同目录临时文件经过 flush、fsync 和权限复制后用 `os.replace` 替换；失败会清理临时文件且不破坏原文件。
- 写入后重新读取磁盘字节并验证新哈希，成功后把新哈希设为最新观察，同时保留旧读取哈希；冲突返回 `hash_conflict` 并明确要求重新读取。
- 完整测试为 `60 passed, 2 skipped`，严格 mypy 检查通过；跳过项仍是当前 Windows 权限不允许创建文件或目录符号链接。
