# 18 — 执行前重新验证已批准操作

**What to build:** 用户批准只绑定当时看到的精确操作；在真正产生副作用前，Wesly 重新验证路径、哈希、目标类型和作用域，阻止审批后发生的替换或漂移。

**Blocked by:** 17 — 审批高风险文件副作用

**Status:** resolved

- [x] 审批绑定规范化操作指纹，任一参数或效果变化都触发重新评估。
- [x] 执行前重新解析目标并验证全部前置条件。
- [x] 符号链接替换、目标类型变化和文件哈希变化不会沿用旧审批。
- [x] 权限策略异常、审计失败、审批超时或中断均默认拒绝。
- [x] 并发漂移测试证明未授权副作用没有发生且事件顺序可审计。

## Implementation result

- 已批准操作在执行前用原始请求重新规范化；重新计算的指纹、解析目标、敏感性和完整效果必须与用户看到的 `PreparedOperation` 完全一致，否则返回 `operation_drift` 并消费旧批准。
- 每个文件效果执行前再次解析原始路径并核对存在性、普通文件类型、硬链接数、前置哈希、目标父目录、移动目的地和作用域；原子写在临时文件落盘后、`os.replace` 前再复核一次。
- 已覆盖批准后哈希变化、文件变目录、创建目标被抢占、移动目的地出现、文件链接替换、父目录作用域跳转和暂存期间并发修改；任何漂移都保留用户内容且旧批准不可重放。
- `ApprovalDecided` 记录 `user`、`timeout`、`interrupted` 或 `approval_error` 原因；Windows 交互式终端审批默认 120 秒超时，超时和审批提供器异常均转为拒绝。
- Agent 增加审批审计回调门；审批请求或决定无法可靠记录时以 `permission_error` 停止。审计失败或中断会显式撤销待执行批准，之后即使持有旧对象也不能产生副作用。
- 并发漂移组件测试断言 `ApprovalRequested → ApprovalDecided → ToolCompleted(operation_drift)` 顺序；完整测试为 `92 passed, 4 skipped`，严格 mypy 检查通过。
- 4 个跳过项均为当前 Windows 权限不允许创建文件或目录符号链接；对应普通路径、哈希、类型、目标出现及暂存期漂移路径已实际执行通过。
