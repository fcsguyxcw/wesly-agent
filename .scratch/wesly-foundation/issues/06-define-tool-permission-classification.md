# Define tool permission classification

Type: grilling
Status: resolved
Blocked by: 03, 04

## Question

首版工具操作如何被确定性地划分为自动允许、需要批准和禁止三类，批准决定如何进入执行结果与审计历史？

## Answer

权限不按工具名称或模型理由判断，而按解析后的实际影响判断。工具参数通过 schema 校验后生成不可变 `PreparedOperation`，包含 capability、规范化真实目标、作用域、副作用、可逆性、敏感性、前置状态及安全相关参数；策略返回 `allow`、`ask` 或 `deny`。执行前必须重新解析目标并验证前置条件，任何安全相关变化都会使原决定失效并重新分类。

首个只读切片的文件规则为：工作区内普通文件的列目录、搜索和读取自动允许；工作区外目标、敏感文件、解析后越界的 symlink/junction 以及大范围读取需要批准；进程密钥、已知凭据存储、特殊设备/管道、无法规范化的目标和协议混淆直接禁止。路径判断依据解析后的真实路径，不能使用字符串前缀。

文件修改只有在目标为工作区内普通非敏感文件、Agent 持有最新观察哈希、使用 patch/原子替换、规模受限且不涉及创建/删除时才可自动允许。创建、删除、移动、重命名、敏感配置、工作区外、批量、哈希冲突、二进制或无可审查 diff 的修改需要批准；无法确定目标、特殊路径、凭据存储或没有可验证前置状态与协调能力的不可恢复写入直接禁止。所有修改保存前后哈希和可审计 diff。

没有 OS 沙箱时，测试、构建和 Git 命令都能执行任意代码，因此首版所有 `run_command` 均需逐次批准，推翻早期“普通构建/测试自动允许”的描述。批准绑定解析后的可执行文件、参数、工作目录、环境覆盖、影响与前置状态；默认执行 argv 而不经过 Shell，需要 PowerShell 语义时将完整脚本文本作为批准对象。首版没有通用网络工具，DeepSeek 网络访问只存在于模型适配器，其他联网行为只能作为需要批准的命令出现。

批准只对完全相同的单次操作有效，不产生持久化或会话级信任。策略记录 `permission_evaluated`；需要用户时继续记录 `approval_requested` 与 `approval_decided`，包含 Session/操作 ID、规范化操作指纹、命中规则、脱敏说明和 `allow_once`/`deny`。拒绝转换为 `ToolResult(error_code="permission_denied")`，模型可换方案但不能复用或修改历史批准。

权限系统严格 fail closed：未知 capability/工具、无法解析目标、规则冲突、策略异常、审计无法可靠写入、用户中断或批准超时均不执行。模型重复请求不能把 `deny` 降级；任何模式都不能绕过凭据过滤与审计。
