# Freeze the implementation roadmap

Type: grilling
Status: resolved
Blocked by: 03, 04, 05, 06, 07, 08, 10

## Question

综合已关闭决策，Wesly 应按什么纵向切片顺序实现，每片的进入条件、验收条件、用户审查点和明确非目标分别是什么？

## Answer

Wesly v1 按以下六个纵向切片实现。每片由 Codex 编写代码、测试、文档并完成验证，用户负责架构取舍与代码审查；只有用户审查通过后才进入下一片。实现使用测试先行的小步循环，提交动作必须另获用户授权。

### 1. 只读仓库调查

- **进入条件**：基础规格和实现票已生成；Python 3.12 环境与 DeepSeek 配置可验证但密钥不进入测试或日志。
- **能力**：`wesly` / `wesly "<task>"` 调用 DeepSeek，经列目录、搜索和读取文件完成多轮只读调查，加载固定 `WESLY.md` 快照，并输出文件依据。
- **验收**：默认测试覆盖票据 07 的首片行为矩阵；手动 live smoke 通过；两个冻结的真实代码理解任务均通过；有限步停止且无未授权读取或密钥泄露。
- **用户审查点**：内部合同是否保持最小；DeepSeek 是否只存在于适配器；CLI 活动与最终依据是否诚实；上下文分页和预算是否可解释。
- **非目标**：文件修改、Shell、Session 持久化、摘要/检索、跨任务记忆。

### 2. 可审查代码修改

- **进入条件**：切片 1 审查通过，所有默认测试为绿；修改相关权限与恢复前置条件已写成失败测试。
- **能力**：Agent 基于最近观察哈希生成并应用小范围 patch，展示 diff，以原子写入更新工作区并记录前后哈希。
- **验收**：工作区内合规单文件修改可完成；创建/删除/敏感/越界/大范围/哈希冲突等分类正确；外部变化不会被覆盖；预期失败生成结构化 ToolResult。
- **用户审查点**：patch 是否最小、可回滚、可审计；权限是否按实际目标/影响而非工具名；是否存在先检查后使用竞态。
- **非目标**：任意命令执行、自动测试、跨进程恢复、批量重构。

### 3. 验证与修复循环

- **进入条件**：切片 2 审查通过；命令批准、结果截断、超时和中断行为已有确定性测试。
- **能力**：Agent 展示完整命令、参数和工作目录，请求一次性批准后运行命令，将安全截断的结果回传模型，并根据测试失败继续修改。
- **验收**：所有 Shell 命令逐次批准；拒绝不被绕过；批准只绑定完全相同操作；测试—修改—复测闭环成功；超时、输出过大、非零退出和 Ctrl+C 均明确停止。
- **用户审查点**：命令执行是否默认 argv、PowerShell 脚本是否整体批准、结果是否脱敏、循环是否有硬限制。
- **非目标**：持久化信任规则、自动批准构建/测试、后台无人值守运行。

### 4. 持久化任务与恢复

- **进入条件**：切片 3 审查通过；事件 schema、迁移、租约、漂移和协调情形均有失败测试。
- **能力**：SQLite 保存追加事件与会话摘要；`wesly sessions`、`resume` 和显式删除可用；崩溃后通过租约、动态文件观察及 Git 状态恢复。
- **验收**：事务中断不产生半状态；同一 Session 只有一个有效所有者；工作区漂移不被覆盖；safe_retry、reconcilable 与 outcome_unknown 按证明结果能力处理；旧 Session 可迁移和恢复。
- **用户审查点**：事件是否不可覆盖、摘要是否只是投影、文件哈希是否在每次成功观察后更新、恢复是否诚实处理未知结果。
- **非目标**：云同步、多用户、跨设备恢复、自动删除历史。

### 5. v1 产品硬化

- **进入条件**：切片 4 审查通过；核心闭环已能用于真实个人仓库。
- **能力**：补齐统一权限审计、敏感数据脱敏、错误分类、数据库迁移/备份、Session 固定指令快照、Ctrl+C、`--verbose`、Windows 安装与升级体验。
- **验收**：权限/审计异常 fail closed；未知工具与 capability 被拒绝；凭据不进入输出、事件和评估资产；Windows 新安装、升级、运行、恢复和卸载路径得到验证。
- **用户审查点**：默认体验是否足够简洁；诊断是否可追溯但不泄密；安装与数据位置是否清楚；ADR 与代码是否一致。
- **非目标**：GUI、Web UI、远程沙箱、多 Agent、插件市场、通用网络工具。

### 6. v1 能力验收与发布边界

- **进入条件**：切片 5 审查通过；三类仓库与 10 个任务的版本化规格在执行前冻结。
- **能力**：运行完整自动化套件、live smoke 和三仓十任务评估，生成不可覆盖结果与人工审查记录。
- **验收**：至少 8/10、每类至少 1 个、两个理解任务全部通过；未批准副作用、凭据泄露、审计缺失及依赖用户手改代码为零；失败、blocked 和重试历史全部保留。
- **上下文证据门**：若任一 v1 任务达到 56K 输入预算的 70% 或产生 context_limit，则发布前另立决策票并实现基础压缩策略；否则压缩进入 v1.1。
- **用户审查点**：成功条件是否事前冻结、失败是否诚实、能力声明是否严格限于固定仓库/任务/预算。
- **非目标**：宣称达到 Codex/Claude Code 整体水平，或用 10 个任务推导普遍软件工程能力。

Wayfinder 到此只交付决策路线，不直接实现。下一流程必须用 `to-spec` 将地图及链接票据折叠为一份自洽规格，再用 `to-tickets` 产生 blockers-first 的实现票；每张实现票在新鲜上下文中通过 `implement` 与 TDD 完成并经用户审查。
