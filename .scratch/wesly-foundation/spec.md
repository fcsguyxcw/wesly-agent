# Wesly v1 产品规格

Status: ready-for-agent

## Problem Statement

现有通用 Coding Agent 已经证明了“模型调用工具完成软件工程任务”可行，但直接使用第三方产品无法满足本项目的核心目的：构建一个能够长期自用的本地 Coding Agent，并在亲自审查实现的过程中理解 Agent 运行时、权限、上下文、持久化和评测之间的架构取舍。

Wesly 不能只是一次演示。它需要逐步形成真实的仓库级软件工程闭环：理解任务、调查仓库、规划、修改、验证、迭代和报告；同时所有高风险行为都必须经过明确授权，执行过程必须可见，失败必须可解释，恢复不能靠猜测。

首个版本面临的主要问题是：

- 如何让模型可靠地调用本地工具，而不让模型供应商的数据格式渗透到 Agent、会话、CLI 和测试中。
- 如何在没有操作系统沙箱的前提下，用细粒度权限决策限制文件和命令副作用。
- 如何保存完整任务历史，同时让模型上下文构建保持显式、可审计，并在超出预算时停止而非静默丢弃信息。
- 如何让中断后的任务根据真实工作区状态恢复，而不是重复执行结果未知的副作用。
- 如何用固定任务和机器可验证结果判断 Wesly 是否已经达到可日常使用的程度，而不是只证明程序能够运行。

## Solution

Wesly v1 是面向单用户、运行在 Windows 本地终端中的 Python Coding Agent。它采用模块化单体：CLI、Agent 循环、模型适配器、工具、权限、上下文和会话属于同一进程和代码库，但通过稳定的内部契约分离职责。

产品通过六个可独立验收的纵向切片交付：

1. 只读仓库调查：完成 DeepSeek 调用、Agent 循环、可见活动日志、目录浏览、搜索和文件读取。
2. 可审查编辑：加入受约束的文件修改、差异展示、文件哈希和原子写入。
3. 验证与修复闭环：加入每次都需审批的命令执行，让 Agent 能根据测试反馈继续修复。
4. 持久任务：加入 SQLite 事件历史、Session 管理、独占租约、工作区漂移检测和恢复协调。
5. v1 加固：完成审计、脱敏、错误分类、数据库迁移与备份、稳定项目指令、Ctrl+C 和 Windows 安装体验。
6. 固定评测：在三个冻结仓库上运行十个覆盖理解、修复、功能、重构和测试的任务，以客观门槛决定是否发布。

v1 使用 DeepSeek 的 OpenAI 兼容 Chat Completions 接口，但供应商协议只存在于模型适配器中。Agent 依赖 Wesly 自己定义的请求、响应、工具调用、工具结果和运行事件类型。模型返回的工具参数始终被视为不可信字符串，必须依次经过工具存在性、JSON、参数模式、权限和执行前置条件校验。

所有操作先规范化为不可变的操作描述，再由权限策略按其实际效果作出允许、询问或拒绝决定。普通工作区内只读操作可以自动执行；受严格前置条件保护的单文件修改可自动执行；所有命令执行都必须逐次审批。未知操作、敏感数据访问、特殊文件和审计失败均默认拒绝。

完整历史持久化与模型上下文构建是两个独立职责。SQLite 保存追加式事件历史；`chronological-v1` 上下文策略只按顺序装配当前 Session 的有效历史、固定项目指令、当前工作区信息和工具定义，不做摘要、检索、跨任务记忆或静默截断。达到上下文预算时，Wesly 在调用模型前明确停止并说明预算构成。

## User Stories

1. 作为用户，我希望运行 `wesly "任务"` 就能创建一个新 Session，以便直接开始仓库级任务。
2. 作为用户，我希望不带任务运行 `wesly` 时得到清楚的使用提示，而不是模糊失败。
3. 作为用户，我希望每次普通运行默认创建新 Session，避免意外继承旧任务的上下文。
4. 作为用户，我希望显式列出、恢复和删除 Session，以便控制持久任务的生命周期。
5. 作为用户，我希望删除 Session 前必须确认，避免误删完整历史。
6. 作为用户，我希望在终端看到模型调用、工具调用、审批和最终状态的简洁活动日志，以便知道 Agent 当前在做什么。
7. 作为用户，我希望普通输出保持简洁，同时能用详细模式查看安全的诊断信息，例如耗时、标识、token 用量和结果是否分页。
8. 作为用户，我希望详细模式永远不显示 API 密钥、凭据、完整敏感内容或模型隐藏思考。
9. 作为用户，我希望按 Ctrl+C 后当前任务安全中断并留下可理解的状态，而不是损坏 Session 或数据库。
10. 作为用户，我希望成功结果包含答案、真实文件证据和简单运行统计，以便检查结论来自哪里。
11. 作为用户，我希望失败结果说明原因、最后动作和可行建议，并且只有真正可恢复时才提示恢复。
12. 作为用户，我希望 Agent 能列出工作区目录，以便建立仓库结构认识。
13. 作为用户，我希望 Agent 能按文本搜索仓库，以便定位定义、调用点和配置。
14. 作为用户，我希望 Agent 能读取普通文本文件的指定范围，以便基于真实代码回答或修改。
15. 作为用户，我希望列表、搜索和读取结果采用显式分页，以便大结果不会被静默截断。
16. 作为用户，我希望工具结果过大时得到明确错误或下一页游标，而不是收到看似完整但实际残缺的数据。
17. 作为用户，我希望只读调查可以连续进行多轮，直到模型有足够证据回答问题。
18. 作为用户，我希望模型直接回答时不被强迫调用工具，但引用文件时必须有真实读取或搜索证据。
19. 作为用户，我希望 Agent 不能借由路径穿越、符号链接或目录联接逃出授权工作区。
20. 作为用户，我希望访问工作区外部、敏感位置或范围过大的只读目标前先得到审批。
21. 作为用户，我希望环境变量中的密钥、凭据存储、设备、命名管道和未知特殊文件默认不可读取。
22. 作为用户，我希望 Agent 修改文件前展示可审查的差异，以便理解具体变更。
23. 作为用户，我希望工作区内普通、非敏感、已存在的单个文本文件只有在版本仍匹配时才允许自动修改。
24. 作为用户，我希望创建、删除、移动、重命名、批量修改、二进制修改或工作区外修改都必须先审批。
25. 作为用户，我希望文件修改采用补丁或原子替换，避免半写入文件。
26. 作为用户，我希望每次成功读取或修改文件后记录当时的真实磁盘哈希，以便后续漂移检测使用最新已知版本。
27. 作为用户，我希望同一文件从哈希 A 修改到哈希 B 后，恢复时与 B 比较，同时历史仍保留 A 和 B。
28. 作为用户，我希望执行测试、构建或其他命令前每次都看到审批，因为这些命令可能执行仓库中的任意代码。
29. 作为用户，我希望命令审批展示可执行程序、参数、目标、原因和工作区，以便作出知情决定。
30. 作为用户，我希望一次审批只适用于完全相同的规范化操作；参数或目标变化后必须重新评估。
31. 作为用户，我希望拒绝操作后 Agent 收到结构化的权限拒绝结果，以便调整方案而不是崩溃。
32. 作为用户，我希望权限系统发生未知异常、审批超时、中断或审计失败时默认拒绝执行。
33. 作为用户，我希望项目级规则写在固定名称 `WESLY.md` 中，以便清楚知道哪些文件会影响 Agent。
34. 作为用户，我希望全局规则来自 `%USERPROFILE%\.wesly\WESLY.md`，工作区规则来自从根目录到目标目录范围内的 `WESLY.md`。
35. 作为用户，我希望更接近目标文件的 `WESLY.md` 优先于祖先和全局规则，但不能覆盖内置安全规则或当前明确指令。
36. 作为用户，我希望创建 Session 时扫描并固定所有适用的 `WESLY.md`，恢复时仍使用原快照，避免规则在任务中途悄悄改变。
37. 作为用户，我希望修改 `WESLY.md` 后通过新建 Session 使规则生效，而不是热重载旧 Session。
38. 作为用户，我希望指令扫描跳过依赖、构建产物和版本控制目录，并拒绝向工作区外跳转的链接。
39. 作为用户，我希望单个指令文件和全部指令有明确大小上限；超限时整体失败，不能只注入一部分规则。
40. 作为用户，我希望 DeepSeek API 密钥只从 `DEEPSEEK_API_KEY` 环境变量读取，且不会被写入 Session、日志或错误输出。
41. 作为用户，我希望模型名称可以配置，避免产品核心依赖某个会变化的供应商别名。
42. 作为用户，我希望供应商特有的响应字段、缓存信息、用量和错误只由 DeepSeek 适配器理解，以便 Agent 和测试保持稳定。
43. 作为用户，我希望无效 JSON、未知工具、参数错误和正常工具失败被转成明确结果，而不是让整个进程异常退出。
44. 作为用户，我希望编程错误和进程级故障不会被伪装成普通工具失败，以便真正的问题能被发现。
45. 作为用户，我希望单次运行有模型轮次和工具调用上限，防止失控循环。
46. 作为用户，我希望达到轮次、工具或上下文限制时看到准确停止原因，而不是得到伪造的成功答案。
47. 作为用户，我希望模型上下文只包含当前 Session 的有效历史、必要工作区元数据、项目指令和工具契约，不包含其他 Session、未读文件、整个环境或数据库。
48. 作为用户，我希望工具输出被明确标记为不可信数据，不能通过文件内容自行授予权限或改变安全规则。
49. 作为用户，我希望 v1 不静默摘要、删除或压缩历史；如果下一次请求超过 56K 输入预算，必须在 API 调用前停止。
50. 作为用户，我希望系统为模型输出保留 8K token，并记录供应商实际用量，以便理解成本和限制。
51. 作为用户，我希望完整 Session 历史保存在本机 SQLite 中，即使其中一部分没有进入某次模型上下文也仍可审计。
52. 作为用户，我希望 Session 的事件只追加不覆盖，并由可查询的当前状态投影提供快速列表和恢复。
53. 作为用户，我希望写入事件和更新 Session 当前状态处于同一事务，避免两者不一致。
54. 作为用户，我希望持久化前完成脱敏，并默认无限保留 Session，直到我显式删除。
55. 作为用户，我希望同一 Session 同时只能被一个执行者修改，以免两个进程交错写入。
56. 作为用户，我希望只读列出 Session 不需要获取独占租约，而恢复或继续执行必须获取租约。
57. 作为用户，我希望租约失去心跳并过期后，接管操作必须给出明确警告而不是静默抢占。
58. 作为用户，我希望 Session 记录仓库根目录、Git HEAD、可选分支、工作区脏状态和规范化状态指纹，以便恢复时识别漂移。
59. 作为用户，我希望只读和幂等的未完成操作能够安全自动重试。
60. 作为用户，我希望有副作用的未完成操作先根据前置状态、后置条件、幂等键或外部查询协调结果，再决定是否恢复。
61. 作为用户，我希望只有在副作用结果仍无法确定时才被要求人工决定。
62. 作为用户，我希望模型请求重试被记录为新的尝试和成本，而不是覆盖第一次调用。
63. 作为用户，我希望数据库格式有显式版本，并能通过事务性迁移升级。
64. 作为用户，我希望较复杂迁移前有备份；较新版本数据库被旧程序打开时拒绝写入。
65. 作为用户，我希望每个纵向切片都通过自动化测试和人工审查后再进入下一片，以便逐步理解架构取舍。
66. 作为用户，我希望正式评测使用冻结仓库、固定提交、固定提示、检查项、禁止变更和预算，以便结果可重复。
67. 作为用户，我希望十个评测任务覆盖仓库理解、缺陷修复、功能实现、重构和测试，而不是只测程序能否启动。
68. 作为用户，我希望正式任务只有通过、失败、阻塞和无效四种明确状态，并保留所有尝试记录。
69. 作为用户，我希望 v1 发布门槛是至少通过 8/10、每类至少通过一个、两个理解任务都通过，并且安全、审计和人工介入违规为零。
70. 作为用户，我希望如果真实评测频繁逼近上下文预算，再以证据触发上下文压缩设计，而不是在首版提前增加复杂度。

## Implementation Decisions

- 使用 Python 3.12 实现本地单进程模块化单体。CLI、Agent、模型、工具、权限、上下文和会话模块各自拥有清晰职责，但不引入分布式服务边界。
- 自研核心 Agent 运行时，不依赖 LangChain、LangGraph、AutoGen 等编排框架。首版采用同步显式循环和迭代器或回调传递运行事件，不引入事件总线。
- Agent 运行时使用稳定的内部模型契约：请求包含消息和可用工具；响应包含文本、工具调用、结束原因和用量；工具调用参数保留为不可信原始 JSON 字符串。
- DeepSeek SDK 和供应商特有格式只存在于适配器内。使用 OpenAI 兼容 Chat Completions 稳定端点，模型标识通过配置提供，不固化为领域常量。
- 首个纵向切片使用非流式工具调用；文本流式输出可以在适配器契约验证后加入。首片关闭供应商思考模式，不依赖流式工具调用片段。
- 工具调用校验顺序固定为：工具是否存在、JSON 是否可解析、参数是否符合模式、操作是否获准、执行前置条件是否仍成立。
- 预期内的工具失败返回结构化工具结果；编程错误、数据库一致性错误和进程级故障进入运行失败路径。
- 默认每次运行最多进行 12 次模型轮次和 30 次工具调用。完成、轮次上限、工具上限、供应商错误、上下文上限和内部错误必须成为可区分的停止原因。
- CLI 使用可滚动活动日志，不在 v1 构建全屏仪表盘。审批只提供“本次允许”或“拒绝”，不建立跨操作的永久信任。
- 工具结果统一使用显式分页元数据，包含返回范围、是否还有内容和下一页游标。任何层都不得静默截断。
- 所有工具请求先转换成不可变的规范化操作，包含能力、解析后的目标与范围、预期副作用、可逆性、敏感性和前置条件。权限策略判断操作效果，而不是只判断工具名称。
- 普通工作区内文件的列出、搜索和读取默认允许；工作区外部、敏感范围、越界链接或过宽读取需要审批；凭据、设备、命名管道和无法识别的特殊目标拒绝。
- 文件写入只在普通、非敏感、已存在的单文件目标满足最新观察哈希、变更有界且通过补丁或原子替换完成时允许自动执行。创建、删除、移动、重命名、批量、二进制、外部或哈希冲突操作必须审批。
- 所有命令执行逐次审批。审批对象优先表示为可执行程序和参数；完整 PowerShell 脚本本身就是待审批操作，不能通过笼统的“运行测试”描述隐藏实际命令。
- 批准只绑定规范化操作指纹一次。目标、参数、工作目录、环境影响或其他效果发生变化时重新评估。
- 权限评估、审批请求和审批决定都写入审计事件。未知能力、策略异常、审计失败、超时或中断一律默认拒绝。
- v1 不提供通用网络工具。除 DeepSeek 模型适配器外，网络访问只能作为经过审批的命令效果发生。
- 每次成功读取或修改文件后从磁盘计算哈希并追加观察事件。恢复使用该文件最新一次成功观察的哈希，同时保留完整历史。
- Git 基线由仓库根、HEAD、可选分支、是否存在未提交修改和规范化工作区状态指纹组成。
- 持久化使用 `%LOCALAPPDATA%\Wesly\wesly.db` 中的 SQLite。事件历史只追加，Session 当前状态作为投影维护；事件追加和投影更新使用同一事务。
- Session 默认长期保留，只有显式删除才移除。进入持久层前完成凭据与敏感信息脱敏。
- 修改 Session 状态前获取独占租约；租约记录所有者、进程、获取时间、心跳和过期时间。采用约 60 秒的保守失效窗口，过期接管必须显式提示。
- 恢复将未完成操作分为安全重试、可协调和结果未知。可协调操作先利用前置状态、后置条件、幂等键或外部查询证明结果；无法证明时才要求人工决定。
- SQLite 使用用户版本和事件载荷版本。升级采用向前、事务性的迁移，非平凡迁移先备份；程序遇到更高版本数据库时拒绝写入。
- 模型上下文由版本化 ContextBuilder 构建，外部契约稳定包含指令、消息、工具和预算。v1 固定使用 `chronological-v1`。
- `chronological-v1` 按顺序包含版本化系统指令、当前任务、规范化工作区与 Git 元数据、当前工具模式、当前 Session 的消息和工具交互。它不读取其他 Session、整个仓库、全部环境变量、数据库、未读文件、完整差异或隐藏思考。
- 产品上下文窗口按 64K 规划，其中输入预算 56K，输出保留 8K。调用前保守估算，调用后记录实际用量。超预算不调用供应商 API，而是以 `context_limit` 阻塞 Session。
- 项目指令只识别全局和工作区范围内固定名称 `WESLY.md`。不兼容读取 `AGENTS.md`、`CLAUDE.md`、`CODEX.md`、README、代码注释或 Git 配置。
- 指令优先级为：内置安全规则、当前用户明确指令、最近目录规则、各级祖先规则、工作区根规则、全局规则、普通工具数据。
- 创建 Session 时扫描并固定全部适用指令及其来源、范围和哈希；恢复沿用快照，不热重载。规则变更只对新 Session 生效。
- 指令扫描不跟随工作区外的符号链接或目录联接，并跳过版本控制、虚拟环境、依赖、缓存和构建产物目录。只接受 UTF-8 普通文件，单文件上限 16 KiB、合计上限 32 KiB；超限整体失败。
- 按六个纵向切片实现，每片必须包含真实可运行功能、自动化验证、人工审查点和明确非目标。提交代码前仍需用户显式批准。

## Testing Decisions

- 最高价值测试缝是 `ModelClient`：用脚本化假模型精确控制模型轮次、工具调用、无效参数、供应商错误和结束原因，从而对 Agent 循环进行确定性验证。
- 只伪造模型客户端、时钟与 ID 生成、审批输入以及真正的外部服务。Agent 循环、工具注册与参数校验、权限策略、路径解析、临时文件系统和临时 SQLite 必须使用真实实现。
- DeepSeek 适配器使用脱敏响应样本进行契约测试，验证供应商格式向 Wesly 类型的映射、错误分类、用量和工具参数保留。真实 API 只用于显式 smoke 或评测，不属于默认测试套件。
- 测试分为四层：纯规则和类型的单元测试；真实 Agent、工具、权限、文件系统和 SQLite 的组件或集成测试；以子进程运行 CLI 的端到端测试；显式启用的真实模型 smoke 与固定评测。
- 首片必须覆盖：模型直接回答；列目录；搜索后读取；连续多工具调用；无效 JSON；未知工具；路径逃逸与越界链接；文件缺失、解码失败和读取失败；供应商错误；轮次和工具上限；Ctrl+C；没有真实证据却声称引用文件。
- 首片验收不仅检查终端可见活动，还必须断言：未授权操作没有发生；失败进入正确的工具结果或运行失败；CLI 退出码与文案匹配；事件顺序完整；日志、数据库和异常不包含密钥。
- 编辑切片使用临时真实仓库验证哈希观察、并发漂移、补丁应用、原子写入、差异展示和审批指纹。测试必须证明修改后的最新哈希替代旧哈希成为恢复基线。
- 命令切片使用受控测试命令验证逐次审批、参数变化重新审批、拒绝路径、超时、中断、输出分页和副作用审计，不将“测试命令”假设为天然安全。
- 持久化切片使用真实临时 SQLite 验证事件与投影同事务、租约竞争与过期接管、Git 漂移分类、恢复协调、迁移、备份和较新数据库拒写。
- 上下文测试必须检查消息顺序、指令优先级、指令快照、工具结果不可信边界、显式分页、56K 输入预算、8K 输出保留以及超限前不发出 API 请求。
- 正式 v1 评测使用三个仓库：熟悉的个人 Python 仓库、陌生的小型开源 Python 仓库、隔离的 Wesly 自身副本。
- 正式评测包含十个任务：两个仓库理解、两个缺陷修复、两个功能实现、两个重构、两个测试任务。每个任务冻结仓库与提交、提示、环境准备、机器检查、禁止变更、验证方式和预算。
- 结果状态只有 `pass`、`fail`、`blocked`、`invalid`。正式运行默认单次尝试；供应商瞬态错误可以追加新尝试，但不得删除或覆盖原尝试。
- v1 通过门槛为至少 8/10，每个任务类别至少通过一个，两个理解任务都通过，并且未经授权副作用、审计缺口、秘密泄露和人工代改均为零。
- 评测任务规格版本化保存，运行产物不可变且经过脱敏。评测用于验证 Agent 的真实能力，不把“程序能启动”当作能力通过。
- 如果任一真实任务达到 56K 输入预算的 70%，或出现 `context_limit`，则创建新的架构决策并在发布前评估上下文压缩；没有证据时压缩、检索和 Memory 不进入 v1。

## Out of Scope

- 桌面 GUI、Web UI 和完整全屏 TUI。
- 云端执行、远程沙箱和无人值守托管。
- 多用户、账号体系、权限角色和团队协作。
- 多 Agent 编排、Agent 市场和插件市场。
- 浏览器控制、通用桌面控制和任意 MCP 客户端。
- 跨任务长期记忆、Memory MCP、知识库检索和默认跨 Session 注入。
- 没有评测证据触发的自动摘要、上下文压缩、检索式上下文和静默历史丢弃。
- 自动部署、CI 平台集成和默认网络工具。
- 模型训练、微调和供应商能力研究平台。
- 针对非 Python 生态的专门工作流优化。
- 永久信任命令、一次批准整个任务或基于命令名称猜测安全性。
- 宣称整体达到或超过 Codex、Claude Code 等产品；v1 只对固定任务和已验证边界作出能力声明。

## Further Notes

- 本规格由 `.scratch/wesly-foundation/map.md`、已解决决策票据、领域词汇表和当前有效 ADR 汇总而成；被 ADR-0007 取代的旧权限决策不再作为实现依据。
- CLI 交互原型只用于验证活动日志、审批和结束状态的呈现方式，不是生产代码，也不能代替自动化验收。
- DeepSeek 契约以 2026-07-22 保存的官方资料研究快照为基线。模型标识和供应商扩展可能变化，因此实现必须保留配置和适配器边界，并在首片执行一次显式真实 API smoke。
- 第一片故意不包含写入、命令、SQLite、摘要或 Memory，但其内部模型类型、工具结果、事件和上下文策略必须能被后续切片沿用；不能把首片写成一次性演示代码。
- 用户负责架构取舍和代码审查；Codex 负责实现、测试、文档和验证。每个切片开始前以本规格和有效 ADR 为边界，出现新架构问题时先形成可审查决策，再修改范围。
- `ready-for-agent` 表示需求与关键决策已经足以开始第一纵向切片，不表示整个 v1 已实现或已通过评测。
